# Mini Code Agent

一个在指定工作目录中读代码、改文件、执行命令的终端助手。Agent 循环使用 Python 编写，模型通过标准库 HTTP 客户端接入，工具用 Pydantic 生成参数 schema 并校验输入。可以使用离线 Mock 验收。

## 五分钟运行

从提交仓库根目录先进入 `问题二` 子目录，以下命令均在该目录执行。

安装 Python 3.10+ 和 uv。首次同步需要下载依赖，之后的 Mock 运行和测试都可离线完成。

```sh
uv sync --frozen
uv run --frozen mini-code-agent --provider mock "列出工作目录的内容"
uv run --frozen python -m unittest discover -v
```

内置 Mock 固定演示列目录和读取结果。要接入真实模型，编辑项目根目录的 `.env`。从新检出的仓库启动时，可以先从模板复制一份：

```powershell
if (!(Test-Path -LiteralPath .env)) { Copy-Item .env.example .env }
notepad .env
```

模板预填了两种按量付费接口的地址。使用 OpenAI 兼容接口时设置 `MINI_AGENT_PROVIDER=openai`，填写 `OPENAI_MODEL` 和 `OPENAI_API_KEY`。使用 Anthropic 兼容接口时改为 `MINI_AGENT_PROVIDER=anthropic`，填写 `ANTHROPIC_MODEL` 和 `ANTHROPIC_API_KEY`。模型名和密钥均来自相应平台。将文件保存为 UTF-8，然后在项目根目录启动：

```powershell
uv run --frozen mini-code-agent
```

末尾附任务文本会执行单轮然后退出。省略任务文本会进入连续对话，输入 `/exit` 退出。`/model anthropic <模型名>` 会在当前会话使用配置中 Anthropic 的地址和密钥。通过 `uv run --frozen mini-code-agent --resume <会话ID>` 可在原工作目录继续。修改配置文件后重新启动即可生效。

| 设置 | 用途 |
| --- | --- |
| `MINI_AGENT_WORKSPACE` | 在 `.env` 中设置新会话的工作目录，例如 `MINI_AGENT_WORKSPACE=D:/agent_work/c-practice`。启动时自动创建缺失的目录及其父目录。相对路径以该 `.env` 所在目录为起点，留空则使用启动目录 |
| `--workspace` | 为新会话临时覆盖工作目录。`--resume` 沿用原会话目录，显式传入的目录须与原目录一致 |
| `--env-file <路径>` | 读取指定的 dotenv 文件，也支持 `--config` 别名。默认读取启动目录的 `.env`，指定 `--workspace` 仅改变工具工作目录 |
| `--provider`、`--model`、`--base-url` | 临时覆盖对应选项。真实密钥放在 Git 忽略的 `.env` 中，仓库中的 `.env.example` 用作无密钥模板 |
| `--max-steps`、`--context-window` | 每轮模型调用上限默认 30，上下文预算默认 32768 个估算 token |
| `--yes` | 跳过写文件、编辑、Shell 命令的逐项确认 |
| `--mock-script <路径>` | 指定 UTF-8 JSON 数组，每次模型调用消耗一个元素。数组耗尽时报告错误 |
| `MINI_AGENT_HOME` | 在 `.env` 中指定会话快照与日志的保存目录，例如 `D:/agent_work/mini_code_agent_sessions`。启动时自动创建目录及其父目录。相对路径从该 `.env` 所在目录算起。未填写时使用同名系统环境变量，再回退到用户主目录下的 `.mini-code-agent` |

模型设置取自命令行和 `.env`。启动目录缺少 `.env` 时才读取系统里的模型环境变量，均未指定协议时使用离线 Mock。显式指定的文件缺失或语法有误时会报告错误。程序支持引号、注释和值中的等号，按字面值使用密钥。文件工具会排除当前加载的配置文件。

例如将下列内容保存为 `demo.json`，运行 `uv run --frozen mini-code-agent --provider mock --mock-script demo.json "创建说明文件"`，输入 `y` 可看到文件落盘。输入 `n` 会得到拒绝结果，循环继续消费下一条脚本响应。

```json
[
  {"calls":[{"id":"w1","name":"write_file","arguments":{"path":"hello.txt","content":"你好！\n"}}]},
  {"content":"本次离线演示结束。"}
]
```

## 如何描述编程任务

简短的任务也可以直接输入。新启动或恢复会话时，程序在 PATH 中按已知名称查找一次 C/C++ 编译器，并把结果、操作系统、Shell 和工作目录提供给模型。检测只检查程序入口，实际编译成功后才能报告通过。单文件任务先交付源码；缺少适用编译器时提示“未编译验证”。已有项目优先沿用原有构建和测试方式。

需要精确控制交付内容时，写清目标、约束和可观察的预期结果。例如：

> 用 C99 在 bfs.c 中实现从指定起点遍历无向图的 BFS。顶点按加边顺序访问。用边 0–1、0–2、1–3，以 0 为起点运行，预期输出为 `0 1 2 3`。请编译并核对结果。

排查缺陷时可以写成「运行哪条命令可以复现、预期结果是什么、实际看到了什么」。模型会收到针对性修复和同项复测的提示；最终是否通过，应以实际测试或输出比对为准。

## 模块和消息流

`cli.py` 读取命令行选项，结合 `config.py` 的 dotenv 配置选定模型与工作目录。`engine.py` 将用户任务追加到会话，把历史消息及六个工具的参数定义传给 Provider 的 `complete` 方法。模型返回多个调用时，引擎依次调用 `tools.py`，由 `shell.py` 执行系统命令，将每个结果按调用 ID 回填，再进入下一次模型请求。`storage.py` 保存会话检查点和脱敏日志。

内部消息统一包含 `role` 和 `content`。助手消息的 `calls` 列表中，每项保存 `id`、工具名 `name` 和原始参数字符串 `arguments`。保留原始参数使截断的 JSON 也能得到明确的失败结果。工具消息用 `id` 关联调用，用 `ok` 和 `content` 表示执行状态与结果。`providers.py` 负责将这些消息转换成 OpenAI 的 `tool_calls` 或 Anthropic 的 `tool_use` / `tool_result`，并把两种流式响应还原为相同结构。Mock 也实现相同的调用接口，因此测试可以替换模型而复用真实的引擎和工具。

## 工具、授权与输出

| 工具 | 主要参数及行为 |
| --- | --- |
| `list_files` | `path` 默认当前目录，指定 `pattern` 可递归 glob 匹配，遍历时跳过 .git、node_modules 和虚拟环境等目录 |
| `read_file` | `path`、可选 `start_line` 和 `end_line`，按从 1 开始的闭区间返回带行号的 UTF-8 文本。指定结束行时读到该行即停，区间输出截断时报告区间内的实际行数 |
| `write_file` | `path`、`content`，显示 diff，确认后创建父目录并原子替换文件 |
| `edit_file` | `path`、`old_string`、`new_string`，旧文本须精确命中一处。保留 UTF-8 BOM 和未修改部分的换行字节 |
| `grep` | `pattern` 正则，可选 `path`、`glob`，返回匹配路径、行号和文本 |
| `run_shell` | `command`、`timeout`（默认 60 秒），从工作目录启动，返回退出码和输出。验证短文本可传 `expected_stdout`，完整标准输出一致且进程正常退出才算通过；统一 CRLF/LF 并忽略一个末尾换行，截断时报告无法核验 |

`list_files` 会区分目录没有可见条目和通配符没有命中；`grep` 在没有匹配时报告 0 处匹配。这三种结果都表示工具执行成功。

文件操作逐级校验相对路径并排除符号链接和 Windows 重解析点。Shell 在当前操作系统用户的权限下运行，经批准的命令可以访问工作目录以外的资源。处理不可信项目时，应在独立的低权限账号、容器或虚拟机中运行。系统提示要求把文件和命令输出当作数据，所有写操作默认还需人工确认。

## 设计和验收

**协议和流式重试。** 两个适配器共用内部消息结构。OpenAI 按调用索引拼接参数，Anthropic 按内容块索引拼接。切换协议时，Anthropic 适配器把同批结果组合成一条 user 消息中的多个 tool_result。终端实时输出文本，只有收到完整结束事件才提交响应并派发工具。遇到超时、429、5xx 或不完整的流，最多请求三次，等待间隔为 1 秒、2 秒。400、401 立即报错。失败尝试已显示的部分文本会留在终端。

**上下文预算。** 目录、读取和搜索结果最多保留 200 行、约 12000 个字符，同时统计总行数。Shell 对两个输出流各保留前 6000 字节。请求前估算历史和工具 schema 的 token 数，按 UTF-8 字节长度给多字节字符更大权重。达到窗口的 80% 后保留当前任务全文、此前任务摘录、文件工具成功修改的路径及最近的进展和待办，再从最近的完整调用批次向前补充。一个 assistant 调用批次与全部结果一起保留或一起舍弃。任务和摘要仍超预算时给出可操作的提示。Shell 的任意副作用无法从调用参数可靠推导，文件变更清单只追踪文件工具。

**中断与恢复。** 执行时按一次 Ctrl+C 会取消本轮并回到交互提示符。空闲时按 Ctrl+C，或在一秒内连续按两次，会退出。单轮命令取消后以 130 退出。Windows 用 Job Object 管理命令进程树，Linux 和 macOS 用独立进程组管理常规子孙进程。流式输出中断时丢弃半条模型回复。完整工具批次先落盘，每个结果再分别落盘。恢复时为缺失结果填入“执行结果未知，请检查现场”，因此即使某条写入已经生效，也不会在恢复时自动重放。

**持久化与观测。** 会话快照先写临时文件并 fsync，再原子替换。进程级文件锁避免同一会话并发写。完整历史用于恢复，上下文压缩仅作用于本次请求。每轮显示输入和输出的词元用量，真实 Provider 返回的用量会跨步骤累加，Mock 可在脚本里指定用量。按会话 ID 查找 `.json` 快照和 `.jsonl` 请求、流式事件与工具结果日志。请求头中的鉴权信息不进入日志，文本中出现的已配置密钥会被遮盖；日志和快照仍包含任务和源码。

**模型异常。** 参数 JSON 无法解析、缺字段、类型不符、工具不存在和用户拒绝都会产生对应调用 ID 的错误结果。遇到 length 或 max_tokens 时跳过整个截断的工具批次。模型把调用写成普通 JSON 文本时，程序请求它改用原生工具通道。单个动作或长度为二、三的序列连续出现三次时，程序跳过触发阈值的动作，补齐该批结果后结束本轮。用户可继续输入下一项任务。

| 测试入口 | 验收场景 |
| --- | --- |
| `tests/test_providers.py` | 两套 SSE、交错参数片段、协议转换、限流与断流重试、客户端错误、Mock |
| `tests/test_engine.py` | 压缩点落在同批结果中间、多个调用只完成一项、恢复与下一轮请求、截断和循环 |
| `tests/test_tools.py` | 5 MB 文件续读、指定结束行停读、空结果、路径越界、文件符号链接、目录符号链接、Windows 目录联接、拒绝与 diff、精确编辑、命令超时和子孙进程清理 |
| `tests/test_cli.py` | 真实 CLI 子进程中拒绝写入、按 ID 恢复、日志密钥遮盖、工作目录绑定 |

**已知局限。** 上下文预算按字符和字节数估算，实际用量随模型的分词器而变化。取消或崩溃后，已落盘的文件和已执行的 Shell 副作用需要现场核对。循环检测只检查长度为一至三的重复动作，更长的循环由每轮步数上限终止。自动化测试使用 Mock、本地 HTTP 服务和协议样本，平台对具体模型的授权及计费需使用真实账号验证。

## 5. AI 使用说明

我使用 Codex 生成了初版 Python 项目，包括模型适配器、Agent 循环、工具、会话存储和测试，又在 Windows PowerShell 中运行真实模型与 Mock，检查终端行为。下面五项是我根据使用结果提出和确认的修改，由 Codex 协助实现并补充验证。

| 遇到的问题 | 做出的修改 | 实际效果 |
| --- | --- | --- |
| 英文注释、模型提示和终端信息阅读不便 | 将注释、系统提示、工具说明、确认、错误、重试和帮助文本改为中文 | 运行时可以直接看出调用了哪个工具、是否成功及失败原因 |
| 每开一个 PowerShell 窗口都要重新设置模型参数和密钥 | 改为启动时读取项目的 `.env`，提供无密钥的 `.env.example`，支持 `--env-file` | 填写一次即可重复使用，可通过命令行临时覆盖模型和地址 |
| 所用平台提供两种兼容接口，地址与厂商默认值不同 | 分别配置平台提供的两个 Base URL，并修正 Anthropic 路径拼接 | 两种协议可以分别指定模型和密钥，模拟请求验证最终的请求路径 |
| 在 Agent 项目根目录启动后，生成的 `dfs.c` 出现在源码旁边 | 引入 `MINI_AGENT_WORKSPACE`，允许 `--workspace` 临时覆盖，恢复会话沿用原目录 | 可以从 Agent 项目启动，并让文件操作、命令执行从指定工作目录开始 |
| 指定全新的目录时启动失败 | 新会话启动时递归创建缺失的工作目录和父目录 | 直接填写新路径即可启动 |

**一次发现和修正。** 我要求持久化模型配置时，AI 最初实现的是用户目录中的 JSON。我在查看使用步骤时发现它与预期的项目级 `.env` 不符，于是明确了配置格式，并提供了平台实际使用的两个地址。修改后用临时 dotenv 文件验证启动、协议切换和密钥脱敏，用模拟 HTTP 请求检查网关路径。

### 运行 DFS、BFS 和 Mock 时发现的问题

在提交 `46ab725` 中，我根据 PowerShell 里的运行记录和截图提出了以下修改，Codex 协助实现并补充了测试。

| 我看到的问题 | 对应修正 |
| --- | --- |
| 我在 Windows 上要求写一个 C 语言 DFS，Agent 却先执行了 `which gcc`。后来运行 BFS 时，它又花了多轮在工作区外找编译器。 | 启动或恢复会话时，程序在 `PATH` 中按已知名称检查一次编译器，把结果、操作系统、实际 Shell 和工作目录交给模型。提示词要求先写源码，再用已有工具验证；缺少适用编译器时报告“未编译验证”。 |
| 我只要求实现一个算法，希望尽快看到能运行的示例，并能判断结果是否正确。 | 我把简单算法的默认交付范围定为核心实现、一个示例和一项能判断对错的检查。Codex 为 `run_shell` 增加了 `expected_stdout`。短输出和预期不一致时，即使程序正常退出也会报告验证失败；提示词要求修复后用同一输入和预期复测。 |
| 看到 Shell 列出工作区外的路径后，我对照题目重新检查了文件工具的沙箱边界。 | 五个文件工具统一校验工作区相对路径，递归列目录和搜索在判断条目类型前先排除链接。文件符号链接、目录符号链接和 Windows 目录联接各有独立用例。提示词也要求模型用文件工具浏览项目；经用户批准的 Shell 命令仍按系统账号权限执行。 |
| 我用 Mock 列出空工作区，终端只显示“成功”，下面一片空白。有文件时，第一项又紧跟在 `[结果：成功]` 后面。 | 工具现在分别说明目录没有可列条目、通配符没有命中和文本搜索有 0 处匹配。成功和失败标签各占一行，文件名或错误信息从下一行开始。 |
| 我原以为日志会保存在项目附近，实际发现它们默认写到了 C 盘的用户主目录。我希望以后统一存到 D 盘。 | 现在可在项目的 `.env` 中指定 `MINI_AGENT_HOME`。程序会创建缺失的目录，并从该位置保存和恢复会话。测试覆盖了配置优先级、目录创建和恢复。 |

检查大日志读取时，Codex 还指出，即使传了 `end_line`，原实现也会扫描到文件末尾。我确认修改后，`read_file` 读到指定结束行就停止；请求全文且结果被截断时仍统计文件总行数。
